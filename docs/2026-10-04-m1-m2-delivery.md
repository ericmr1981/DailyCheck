## 6. 已知问题

1. **3 个浮点脏值在 dev 副本里没有**：spec §7.7.1 的 7 个真实脏值中只有 3 个在 dev 副本里（`0.3399999999999998` / `0.4000000000000005` / `0.20000000000000212`），其余 4 个（`0.3599999999999996` / `0.12999999999999926` / `0.04000000000000048` / `49.5` / `0.5`）需要 INSERT fixture 模拟。**这是变通而非读真实值**。生产副本里都有（prod-data-findings.md）。

2. **`forecast_pure.py` 8 个 pre-existing failure 不归本工作**：在 `tests/test_forecast_pure.py` 等位置已存在 8 个测试失败，与 canonical-item 无关（本工作前已失败）。baseline `pytest tests/ -q --ignore=...` 显示出 13 个 pre-existing failure，本次提交后仍然 13 个，未引入新失败。

3. **`pytest` 未写入 requirements.txt**：环境补装未声明。开发用 `python3 -m pip install pytest` 单次安装即可。**建议 Eric 决定是否要把 pytest 加入 dev-requirements（不放入 prod requirements）**。

4. **wh_002 的 `0.34` 不在脏值列表**：dev 副本里 wh_002 没有 spec 表格里列的 `0.34 / 0.4` 这种 2dp 等价物（实际值是 `0.3399999999999998 / 0.4000000000000005`），但这正是 §7.7.1 想强调的——**类型一致的 REAL 值不能被 round() 后丢失精度**。Test 6（`test_r3b_round_then_compare_would_hide_drift`）已经反向证明 round() 会掩盖漂移。

5. **`canonical_item_aliases` 暂未自动写入**：CSV 灌入路径不写 alias（CSV 没有 alias 列）。`claim_item()` 的 `local_keep_name` 入参路径会写 alias，但 M1 阶段 store_exclusive 批量收编未走该路径。P1-6「别名全局可见」已通过 `get_canonical_item_detail` 的 aliases 字段暴露，下游按需。

6. **`initial_quantity` 列在 wh_001**：5 仓（wh_000/002/003/004/006）无此列；wh_001 有但被排除。迁移代码兼容（用 PRAGMA 检测后跳过），select_item_columns 动态列防止跨仓 SELECT 抛异常。
