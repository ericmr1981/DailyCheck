# DailyCheck Agent 自治开发框架 v0.1

> **核心命题**：以**契约化验收** + **多层自动测试** + **报告比对**替代人工 review，逐步实现 Agent 自治免盯。
>
> 状态：v0.1 初稿，2026-10-13 起草，待 Phase 1 落地验证。

---

## 一、角色与边界

| Agent | 触达范围 | 主要动作 | 明确不许做 |
|-------|---------|---------|-----------|
| **Dev Agent** | 本地 Docker + GitHub PR | 写代码、跑测试、出报告、提 PR | 触碰生产环境、改主分支 |
| **Prod Agent** | 生产蓝绿 + 主分支 | 拉 PR、起绿环境、跑集成验证、切流量、合 PR | 写新业务代码、改契约 |
| **Monitor Agent**（可选） | 生产监控 + 报告归档 | 指标比对、阈值告警、报告存档 | 执行任何变更 |

**边界双锁**：报告门禁 + 权限隔离（Dev Agent 的 SSH key 无 prod 写权限；Prod Agent 无 repo 写权限）。

---

## 二、流程图

### Dev Agent（提 PR 前）
```
需求 → 契约 → 实现 → 多层测试 → 四报告 → 全绿 → 提 PR
                       ↓ 失败                     ↓ 阻塞
                      返工                  报告不全，禁提
```

### Prod Agent（合 PR 前）
```
PR 拉取 → 起绿环境（共享读/隔离写）→ 集成+UI验证 → 验证报告
                                                       ↓ 全绿
                                  切流量（5%→100%）→ 观察窗 → 合 PR → 蓝环境 standby
                                                       ↓ 失败
                                  留绿环境取证 → 打回 PR（附报告）
```

## 三、Dev Agent 多层测试金字塔

| 层 | 工具 | 通过标准 |
|----|------|---------|
| L1 静态扫描 | ruff / mypy / bandit / secretscan | 零新增告警 |
| L2 单元测试 | pytest + 边界 + 异常路径 | 全部绿，覆盖率 ≥ 基线 |
| L3 契约测试 | OpenAPI schema diff / migration 前向兼容 | 契约 diff = 0 或已声明 |
| L4 UI 操作测试 | Playwright 模拟真实用户点击 | 关键路径 100% 绿 |
| L5 本地冒烟 | docker compose up + 健康检查 | 关键页面 200/302 |

### 四份报告（Dev Agent 必出，缺一不收 PR）

| 报告 | 模板 | 用途 |
|------|------|------|
| 1. 需求对齐报告 | [`templates/01-requirement-alignment.md`](templates/01-requirement-alignment.md) | PRD/issue ↔ 代码改动 ↔ 测试覆盖矩阵 |
| 2. 测试报告 | [`templates/02-test-report.md`](templates/02-test-report.md) | 五层结果 + 覆盖率 diff |
| 3. 代码质量报告 | [`templates/03-code-quality.md`](templates/03-code-quality.md) | lint + 复杂度 + 重复率 + 安全扫描 |
| 4. 本地部署预演报告 | [`templates/04-local-deploy-preview.md`](templates/04-local-deploy-preview.md) | compose up → 健康检查 → 关键路径截图 |

## 四、Prod Agent 蓝绿部署

### 4.1 绿环境约束

- **配置严格一致**：同一镜像 + 同一 env 模板（仅端口/URL 差异）
- **共享读流量**：直接连生产 DB 主库只读账号或独立只读副本
- **隔离写流量**：所有写操作走 `dry_run` 模式或 schema 前缀（`green_*`），不污染生产
- **路由独立**：监听 :8091 等独立端口；Nginx/HAProxy 按 host 路由灰度

### 4.2 生产验证报告（Prod Agent 必出）

模板：[`templates/05-production-verification.md`](templates/05-production-verification.md)

1. 集成测试 100% 通过
2. 模拟用户操作 100% 通过
3. **绿 vs 蓝比对**：同一脚本跑一遍，响应/截图 diff < 阈值
4. 性能基线：P95 ≤ 蓝的 1.2x，CPU/内存 ≤ 蓝的 1.3x
5. 回滚演练：开关可秒级切回蓝

### 4.3 切换流程

- 灰度：5% → 50% → 100%（可配）
- 观察窗：100% 后 ≥ 30 分钟无异常
- 合 PR：观察窗过后自动合
- 蓝环境：降级为 standby 保留 7 天

## 五、契约化验收（核心机制）

**Contract as Source of Truth**：review 看契约 diff，不看实现细节。

| 契约类型 | 承载形式 | diff 工具 |
|---------|---------|----------|
| API 契约 | OpenAPI / pydantic | schema-diff |
| 数据契约 | migration 文件 | forward-compat checker |
| 行为契约 | Playwright 脚本 | 脚本 diff + 截图比对 |

报告比对 = 契约执行结果。**报告全绿 ≡ review 通过**。

## 六、自治决策权限

| 级别 | 决策权 | 触发条件 |
|-----|--------|---------|
| L1 | Dev Agent 自主 | 单文件改动 + 四报告全绿 |
| L2 | Prod Agent 自主 | 绿环境报告全绿 + 观察窗无异常 |
| L3 | 需人工 | 跨服务契约变更 / 数据迁移 / 切流量阈值突破 |
| L4 | 必须人工 | 合规、安全事件、生产事故 |

## 七、推进路径

| Phase | Dev Agent | Prod Agent | 人工介入点 |
|-------|-----------|------------|-----------|
| 1 全自动提 PR | ✅ | 人工验证 | review + 人工 Prod |
| 2 自动验证出报告 | ✅ | ✅ 自动验证 | 仅合 PR 决策 |
| 3 闭环 + Monitor | ✅ | ✅ | 仅异常告警 |
| 4 全自治 | ✅ | ✅ | 仅 L4 触发 |

每阶段跨越条件 = 当前阶段连续 N 次零异常 + 报告全绿可追溯。

## 八、DailyCheck 落地判断（现状对照）

### 已有基础
- ✅ CI 零新增约束（`tests/known_failures.txt`）— L1 静态扫描基础
- ✅ 多层测试结构（unit/contract/ui）— 测试金字塔雏形

- ❌ Mac mini Docker 与 wdg_vps Ubuntu 缺统一镜像/env 模板

- ❌ 报告未被版本化，难以做跨 PR 比对

2. ⏳ Mac mini 起一个与 VPS 同构的 docker-compose
