## 2. KPI 计算逻辑（全部落 `reports_health_pure.py`，每条 SQL 带口径注释）

**通用铁律：时间过滤一律用 Python 侧 `datetime.now()` 绑定参数，禁止 SQL
`datetime('now')` —— 生产 CST / SQLite UTC 时区坑，dev 不可复现、生产必现。**

**常量（模块级，改口径只动一处）**：
```python
STALE_DAYS = 7            # 呆滞账龄阈值（天）
DOS_THRESHOLD_DAYS = 7    # 超储可售天数阈值（天）
DOS_WINDOW_DAYS = 30      # DOS 的日均消耗回看窗口（天），与页面 range 解耦
STOCKTAKE_MAX_GAP = 30    # 超期未盘阈值（天）
BOM_OVERUSE_PCT = 10      # BOM 超耗预警阈值（%）
```

### 2.1 库存金额
`SUM(items.quantity × unit_cost)`（全部 items 行，与 /summary 同源）；活跃 SKU 数 = `COUNT(is_active=1)`。

### 2.2 仓级周转率 / 可售天数
复用 `core._compute_summary_metrics`，零新口径：
- 周转率 = 窗口消耗金额 ÷ 平均库存金额（(期初+期末)/2，期初 = 当前库存 − 窗口内净流水反推）
- 可售天数 = 窗口天数 ÷ 周转率
- 窗口消耗金额 = outbound_requests（rolled_back=0 且 reason 非生产领料）+ production_run_items（run 未回滚）

### 2.3 低于安全库存 / 断货
- 断货：`is_active=1 AND quantity=0`
- 低于安全：`is_active=1 AND 0 < quantity < safety_stock`

### 2.4 呆滞（红）—— FIFO 账龄重放
对每个活跃 SKU（is_active=1 且 quantity>0）按时间顺序重放 `stock_movements`，维护 FIFO 层队列（层 = 入库日期 + 数量）：

| 流水 action | 处理 |
|------------|------|
| 补货入库（delta>0） | 压入新层（created_at, delta） |
| 出库 / 调整出库 / 补货删除回滚（delta<0） | 从最老层开始消减（先进先出） |
| 盘点修正 / 盘点调整 / 盘点回滚 / 库存调整 | 按比例缩放所有层，使层总和 = 重放后数量 |

- **呆滞量** = 重放结束时所有「账龄 > 7 天」层数量合计；呆滞金额 = 呆滞量 × unit_cost
- **兜底**（必须实现）：重放终值 ≠ items.quantity（历史漂移）→ 该 SKU 回退"近 7 天零消耗"判定（近 7 天无出库/生产消耗流水则全额呆滞）
- 首条流水之前的初始库存年龄未知 → 按"最老"处理（保守计入呆滞，宁误报不漏报）
- 红呆滞优先于黄超储：呆滞量 > 0 的 SKU 不再算 DOS

### 2.5 超储（黄）—— 可售天数 DOS
- 日均消耗 d = 近 30 天（出库 + 生产消耗量）÷ 30（固定窗口，与页面 range 解耦）
- DOS = quantity ÷ d
- 黄·超储 = 近 7 天**有**消耗（d>0 且近 7 天有出库/生产消耗流水）且 DOS > 7 天
- DOS ≤ 7 天 → 正常

### 2.6 ABC 分类
窗口内消耗金额（口径同 2.2）按 SKU 降序累计：≤80% = A、≤95% = B、其余 = C。

### 2.7 消耗趋势
窗口内按日消耗金额（口径同 2.2），缺失日补 0，取最后 14 点。

### 2.8 补货健康
`restock_requests`：待审批数（status='待审批'）/ 拒绝率（拒绝 ÷ 窗口内总数）/ 窗口补货单数。
⚠️ 表内无状态变更时间戳，「平均审批时长」V1 不做，V2 加列（schema 迁移）后再上。

### 2.9 门店履约
master.db `store_orders` + `store_order_status_history`（当前仓绑定的门店订单）：
- 积压 = status ∈ (pending, approved)；在途 = shipped
- 平均履约周期 = avg(delivered 时间戳 − created 时间戳)，经 history 表逐单取点

### 2.10 盘点质量
`stocktakes`：差异率 = diff≠0 行 ÷ 总行；超 30 天未盘 SKU 数（最后盘点日距今 > 30 天的活跃 SKU）；上次全盘 = MAX(created_at) 距今天数。

### 2.11 生产分析（v2 新增）
数据源：`production_runs`（product_id, output_qty, rolled_back, created_at）+ `production_run_items`（run_id, item_id, planned_qty, actual_qty）+ `products` + `product_bom`。

- **生产批次数 / 产出总量**：窗口内 `rolled_back=0` 的 runs 计数；`SUM(output_qty)`（按产品单位）
- **生产消耗金额**：`SUM(production_run_items.actual_qty × items.unit_cost)`（窗口内未回滚 run），与 2.2 消耗口径的生产部分同源
- **BOM 超耗率**（核心指标）：
  ```
  领料行超耗% = (actual_qty − planned_qty) ÷ planned_qty × 100
  超耗行 = 超耗% > BOM_OVERUSE_PCT(10%) 的行
  仓级超耗率 = 超耗行的超额总量 ÷ 窗口计划总量 × 100
  ```
- **单位产出成本** = 窗口生产消耗金额 ÷ SUM(output_qty)
- **生产超耗明细**（风险段用）：窗口内超耗行按超耗金额（(actual−planned)×unit_cost）降序 TOP 10，列品项/计划/实际/超耗%
- 边界：planned_qty=0 且 actual>0 的行视为 100% 超耗（新建 BOM 缺计划的兜底）；窗口无生产 run 时整卡显示"—"不报错

### 2.12 SKU 级明细指标（⑨ 表，v2.1 新增）
对每个 SKU 逐行计算（口径全部沿用上文，无新定义）：
- 账龄呆滞量 / 呆滞金额 / 最老层入库日：复用 2.4 FIFO 重放结果（重放本来逐 SKU 跑，顺带产出，零额外成本）
- DOS / ABC / 窗口消耗金额：复用 2.5 / 2.6 / 2.2
- 最后出库日 = MAX(created_at WHERE action IN ('出库','生产消耗')相关)；最后入库日 = MAX(补货入库)；最后盘点日 = MAX(stocktakes.created_at)；无记录显示"—"

### 2.13 生产明细（⑩ 表，v2.1 新增）
- **产品维度**：窗口内按 product 聚合未回滚 runs——批次数 / SUM(output_qty) / 消耗金额（actual_qty×unit_cost）/ 单位产出成本（÷output_qty）/ 超耗率（复用 2.11 行级口径按产品汇总）。⚠️ products 表无 category_id，产品维度只能到产品，不能到品类
- **原料品类维度**：run_items → items.category_id 聚合——各品类生产消耗金额、计划总量 vs 实际总量、品类超耗率（同 2.11 公式）；按消耗金额降序

## 5. 用户操作方式与逻辑（详细版）

### 5.1 谁能用、怎么进来
| 角色 | 进入方式 | 直接敲 URL |
|------|---------|-----------|
| staff | 看不到任何入口 | 403 |
| manager / admin | 桌面侧栏「总览 → 库存健康」；移动端「更多 → 总览 → 库存健康」 | 200 |

系统行为：进入时按「当前所选仓」计算全部指标——切仓即切数据，无需页面内再选仓。

### 5.2 每个可交互元素 → 点击后发生什么
| 元素 | 位置 | 点击后行为 |
|------|------|-----------|
| 7 日 / 30 日 / 全部 | 页头 | 跳 `?range=7d|30d|all`，页面重算；非法值服务端回退 7d；URL 可直接分享/收藏，对方打开看到同一窗口 |
| 导出 CSV | 页头 | 下载当前 range 的分段 CSV（总体/ABC+呆滞超储超耗/盘点/**SKU 明细全表**/**生产明细·产品+品类**），utf-8-sig，Excel 中文直开 |
| 明细行「去补货 →」 | ⑧ 段 1 | 跳 `/restock`（入库/补货页），用户在该页提补货单 |
| 明细行「去盘点 →」 | ⑧ 段 5 | 跳 `/stocktake`，对该品项发起盘点 |
| 超耗行 | ⑧ 段 4 | 跳 `/production` 生产记录页，定位对应批次核对领料 |
| SKU 明细列头 | ⑨ | 服务端排序：`?sort=stock_value|consumed|dos|stale`（白名单，默认 stock_value 降序）；无 JS，点击即带参跳转 |
| 品项名 | ⑧/⑨ 各段 | 跳 `/items` 编辑页查看/调整该 SKU |
| 切换仓库 | 全局 ctx-bar | 回到本页但数据变为新仓（指标全部随仓重算） |

### 5.3 读数逻辑（推荐的巡检顺序）
1. **扫 KPI（3 秒判断有没有事）**：红黄数字即风险计数，全绿 → 收工。
2. **有事看结构**：② 趋势看消耗是涨是跌（判断是卖得快还是管得差），③ ABC 确认问题集中在哪类。
3. **定位环节**：④ 补货卡看审批是否积压；⑤ 履约看门店订单是否堵在 pending；⑥ 盘点看差异率是否异常（差异率高 → 库存数据本身不可信，其他指标先打问号）；⑦ 生产看超耗率。
4. **拿行动清单**：拉到 ⑧ 风险明细，从上到下按段处理——排序即优先级（断货 > 呆滞 > 超储 > 超耗 > 未盘）。
5. **处理完回来刷新**：报表纯实时计算，无缓存，处理完刷新即见新数字。

### 5.4 典型作业场景
| 场景 | 操作路径 |
|------|---------|
| **每日开店巡检**（2 分钟） | 看段 1 有没有断货红行 → 有就点「去补货」；看 ⑤ 积压数，堵了去订单管理发货 |
| **周度库存复盘**（10 分钟） | 切「7 日」→ 逐段过 ⑧，呆滞/超储行逐个决定促销/调拨；⑦ 超耗 TOP 拿去和生产同事核对 BOM 或操作习惯 |
| **月度盘点准备** | 切「30 日」→ 看段 5 超期未盘清单 + ⑥ 差异率 → 按清单安排盘点计划 |
| **给老板汇报** | 切对应窗口 → 「导出 CSV」→ Excel 里直接贴 |

### 5.5 边界情况显示规则
| 情况 | 显示 |
|------|------|
| 新仓 / 无任何流水 | 趋势图显示"暂无数据"；趋势/ABC/补货/履约/生产各卡显示"—"；KPI 库存金额正常显示；不报错 |
| 窗口内无生产 run | ⑦ 卡与超耗段整体显示"—"/隐藏 |
| 仓类型为 DC（无门店订单） | ⑤ 履约卡显示"—"（DC 不直接服务门店订单） |
| 某 SKU 重放流水失配 | 该 SKU 回退零消耗判定（用户无感知，口径备注不展开） |

### 5.6 移动端差异

- 明细表横向可滑；跳转按钮热区按移动端既有样式放大。
- 导出 CSV 在移动端同样可用（下载到本机，用 Excel/WPS 打开）。

## 7. 已知局限（数据不支撑，明确不做）

- **批次账龄精度**：账龄由流水重放近似，非真实批次追踪；重放失配自动回退零消耗判定。
- **BOM 超耗粒度**：按领料行 vs BOM 计划比较，无法区分"损耗"与"浪费"；BOM 未维护的产品不参与超耗计算。
- 效期/临期分析（items 无 expiry 字段，需 schema 迁移，V2 单独立项）。
- 供应商到货及时率（无供应商表）。
- 销售联动比率（daily_revenue 稀疏）。
- 平均补货审批时长（restock_requests 无状态变更时间戳，V2 加列）。
