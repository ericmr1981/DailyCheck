## 3. 跨仓同名品项：71 个（dev 只有 7 个）

### 3.1 单位冲突 9 个 —— Q1=deny 下最危险的一类

| 品项 | 各仓单位 |
|---|---|
| 榛子巧克力 | wh_000:桶 / wh_001:**克** / wh_003:桶 |
| 淡奶油 | wh_000:盒 / wh_002:箱 / wh_003:盒 / wh_004:箱 / wh_006:箱 |
| 草莓丁 | wh_000:包 / wh_001:**克** / 其余:包 |
| 草莓酱F | wh_000:罐 / wh_003:件 |
| 试吃勺 | wh_000:箱 / wh_001:**包** / 其余:箱 |
| 进口酸奶粉F | wh_000:包 / wh_002:袋 |
| 迷你冰糕 | wh_000:盒 / wh_001:**个** / 其余:盒 |
| 酸奶粉 | wh_003:包 / wh_006:袋 |
| 餐巾纸 | wh_000:箱 / wh_001:**包** / 其余:箱 |

架构师 v3 §2.4 定的是「单位族 4 字段任一冲突 → 整组冻结 + `conflict_type='unit_conversion'`，**禁止逐字段下发**」。**这 9 个正是该规则的主要负载**，其中「淡奶油」横跨 5 仓且盒/箱混用。

**风险**：如果主数据把「淡奶油」单位定为「盒」，wh_002/004/006 的「箱」会被冻结 → 门店无法记库存。**必须支持「一主数据多单位换算」或「单位由门店自治」**，不能一刀切。

### 3.2 单位分布（说明「箱/包/袋/罐」是采购单位，混用是常态）

各仓单位高度重叠：箱(11-17)、袋(12-14)、包(11-14)、罐(10-19)、桶(1-14)、盒(2-5)。wh_001 特殊——单位是「克/个/袋」而其他仓是「箱/包」，说明 **wh_001（中央仓）粒度最细**。

## 4. 🔴 最紧急：Q1=deny 会让 6 个门店当天无法录单

**事实链**：
1. `rd_001.items = 0` —— 研发中心**一个品项都没有**
2. 生产 431 个品项**全部是门店自建**（`sku` 形如 `WH000-*`，无 `AUTO-*`）
3. 你已拍板 **Q1=deny**（门店不能自建全新品项）
4. 主数据 `canonical_items` 数为 **0**

**推论**：M1 上线后，门店想录入任何一个品项都会走 `check_new_item_policy` 被拒 → 走「品类白名单」或「提交申请给总部」→ **而总部也没有主数据可以批准**。6 个门店全部卡死。

### 必须的补救（按优先级）

1. **主数据必须先有存量**。431 个门店品项需要收敛成主数据项。T22 的种子数据不能再用 dev 那 8 条，必须用**生产 431 条**。
2. **「门店专属」豁免必须开**。431 个品项里相当比例是门店特有的（韩国街店的韩文品名、浦发时光里店的定制物料），Q1=deny 若无白名单，Q1=deny 就是把真实业务推到线下私记——正是架构师 §1.6 论证过要避免的。
3. **单位冲突的 9 个必须人工先裁决**，否则认领时全部卡在 `unit_conversion` 冲突页，队列长度 9 × 多仓 = 数十条，淹没冲突页。

**建议：Q1 从 `deny` 调整为 `deny + 存量白名单`**，即对**已存在的 431 条**走一次性收编（`created_from='claim_merge'`），之后新录入才受 deny 约束。
