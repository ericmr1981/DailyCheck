## 1. 设计寄存器与三轴标定

### 寄存器判定：**Product 寄存器**（设计服务产品）

权限管理是后台工具 UI，不是营销页。标杆是"赢得熟悉感"——管理员应觉得可信、可预测、可键盘操作，而非"惊艳"。

| 维度 | Product 寄存器策略 | 本项目落地 |
|------|-------------------|-----------|
| 色彩 | 克制：中性色为主 + 强调色 ≤10% | 青绿仅在「已授予」格 + 主 CTA 出现 |
| 排版 | Sans-serif，禁用衬线体（Dashboard 铁律） | 延续 PingFang SC / Microsoft YaHei |
| 动效 | 功能性动效，150ms 收敛，无装饰动画 | checkbox 切换、抽屉滑入，仅此 |
| 图片 | 用数据/图标/UI 元素替代照片 | 图标 + 矩阵，零照片 |

### 三轴刻度（本项目标定）

| 参数 | 本项目值 | 理由 |
|------|----------|------|
| **DESIGN_VARIANCE** | **2**（可预测） | 权限矩阵是严格对齐网格；非对称布局会让行列表头错位、勾选取向混乱。对称 = 可用性。 |
| **MOTION_INTENSITY** | **2**（近静态） | 后台工具，仅保留 hover/active/focus 反馈 + 抽屉过渡。高动效 = 分心 = 降低信任。 |
| **VISUAL_DENSITY** | **7**（驾驶舱模式） | 权限点数量大（预估 20-40 个），必须高密度。**>7 的规则生效：禁用通用卡片容器，改用 `border-t` / `divide-y` / 负空间分组。** |

## 2. 对标品牌与设计语言

### 对标品牌（3 个）

1. **Linear — Settings / Members & Roles**（主要对标）
   克制的中性灰底、1px 边框而非阴影、紧凑行高、键盘优先。延续 v2 已确立的「Notion/Linear 风」。
2. **Stripe Dashboard — Team & Permissions**
   权限矩阵的信息密度标杆：分组表头、三态单元格、变更影响提示。
3. **Cloudflare Dashboard — Account Members / Roles**
   内置角色「锁定只读」的表达方式：禁用态 checkbox + tooltip 说明"系统内置，不可修改"。

### 设计语言延续（勿另起炉灶）

- 布局：侧边栏 + 主内容区，延续 `base.html`。
- 容器：白色 `--panel` + 1px `--border` + 10px 圆角 + `0 1px 2px rgba(0,0,0,.04)` 微阴影（对齐 `users-admin.css:12-19`）。
- 抽屉：右侧 360px 滑入，`220ms cubic-bezier(0.22,0.61,0.36,1)`（对齐 `users-admin.css:189-205`）。权限矩阵详情抽屉因内容更宽，**新增 480px 变体**。
- 零依赖铁律：纯 static CSS/JS，内联 SVG，无框架、无图标字体、无 CDN。

### 3.2 新增 token 需求（权限矩阵专用，纳入 Phase 2 DESIGN.md）

> 全部为**语义 token**，禁止在组件里裸写 hex（P0-3 / 红线 4）。命名按用途不按色相。

```css
:root {
  /* ── 权限矩阵单元格三态（核心）──
     学术依据：把「继承」折叠进「授予」是矩阵可用性第一大坑
     （用户取消上级勾选却看到它仍亮着 → 判定 UI 坏了）。
     故三态必须视觉可辨。 */
  --perm-cell-on:        var(--brand);               /* 已授予（可点，源头）*/
  --perm-cell-on-bg:     #ecfdf5;                     /* 已授予底色（teal-50，既有 .is-target 同色）*/
  --perm-cell-inherited: #6b7280;                     /* 继承态（虚线边框，不可点）*/
  --perm-cell-off:       var(--border);               /* 未授予（空描边）*/
  --perm-cell-locked:    #f3f4f6;                     /* 锁定（系统内置不可改）*/
  --perm-cell-locked-fg: #9ca3af;

  /* ── 变更预演（Phase 2 编辑态用，本期预留）── */
  --diff-added:   #2563eb;                            /* 本次新增（蓝）*/
  --diff-removed: #dc2626;                            /* 本次移除（红斜线）*/
  --diff-unchanged: var(--perm-cell-on);              /* 已有不变（绿/teal）*/

  /* ── 权限域分组 chip（订货/库存/品项/报表/管理）── */
  --domain-chip-bg:    #f3f4f6;                        /* 中性化，不用 5 种彩色（避免彩虹矩阵）*/
  --domain-chip-fg:    #374151;
  --domain-chip-active-bg: #ecfdf5;
  --domain-chip-active-fg: var(--brand-ink);

  /* ── 角色标签（复用并 token 化既有硬编码）── */
  --role-tag-builtin-bg: #eef2ff;                      /* 内置角色（靛蓝 tint，沿用现状）*/
  --role-tag-builtin-fg: #3730a3;
  --role-tag-admin-bg:   #fef3c7;                      /* 平台管理员（琥珀，沿用现状）*/
  --role-tag-admin-fg:   #92400e;

  /* ── 矩阵尺寸（结构 token，A1-structure）── */
  --matrix-cell-size:    28px;                         /* 桌面单元格 */
  --matrix-row-h:        36px;                         /* 桌面行高（高密度）*/
  --matrix-sticky-col-w: 160px;                        /* 左侧权限点名冻结列 */
  --drawer-w-wide:       480px;                        /* 权限矩阵详情抽屉（360 太窄）*/
}
```

**强调色用量纪律**：每屏可见 `--brand` 使用 ≤2 处（红线）。矩阵里「已授予」格虽多，但属**同一功能的重复实例**（视为 1 处语义强调），主 CTA 为第 2 处；不再额外加彩色徽章。

**深色模式**：本期**不做**（现有系统全浅色，`users-admin.css:6` 明确"全部用浅色主题"）。仅 token 命名预留，不实现。

### 3.3 字体方向

延续现状并 token 化（P0-3「禁止默认系统字体直出」的合规解法 = 显式声明品牌字体栈，而非强制引入 Web Font）：

```css
:root {
  --font-ui:   "PingFang SC", "Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif;
  --font-mono: "JetBrains Mono", "Fira Code", ui-monospace, monospace; /* 权限点代码 order.create 用 */
}
```

- **正文/UI**：`--font-ui`，14px / 行高 1.5。
- **权限点代码**（`order.approve` 等 dot-notation）：`--font-mono` 12px，`letter-spacing:0` —— dot-notation 命名的可读化见 §5.4。
- 字重三级：400 正文 / 510 表头与按钮 / 590 标题（对齐 token-standard §七）。
- ALL CAPS（如表头 "PERMISSION"）：`letter-spacing:0.06em`。中文表头不加字距。

### 4.1 页面 A — 权限矩阵视图（核心）

```
┌─ 权限管理 ────────────────────────────────────────────────────────────┐
│  [ 权限矩阵 ]  [ 角色列表 ]                          ← Tab 切换        │
├───────────────────────────────────────────────────────────────────────┤
│  工具栏（复刻 users-toolbar 样式）                                     │
│  [ 搜索权限点… ] [域:全部 v] [视图:矩阵|分组 v]        [导出 CSV]      │
├───────────────────────────────────────────────────────────────────────┤
│  图例 / Legend（解释三态 + dot-notation）                              │
│  ● 已授予   ◌ 继承自上级   ○ 未授予   ▨ 系统锁定          格式：      │
│                                                          资源.动作     │
├───────────────────────────────────────────────────────────────────────┤
│  ┌ 冻结列 ┐┌────────── 角色列（横向滚动区）──────────┐               │
│  │ 权限点  │  staff      manager      admin(仓级)     │               │
│  ├─────────┼──────────────────────────────────────────┤               │
│  │ ▾ 订货  │                                          │  ← 域分组折叠 │
│  │ order.  │                                          │               │
│  │ create  │   ●          ●            ●             │               │
│  │ order.  │                                          │               │
│  │ approve │   ○          ●            ●             │               │
│  │ order.  │                                          │               │
│  │ cancel  │   ○          ◌(继承man)   ●             │               │
│  ├─────────┼──────────────────────────────────────────┤               │
│  │ ▸ 库存  │  … （折叠，点击展开）                     │               │
│  │ ▾ 品项  │   …                                       │               │
│  │ ▾ 报表  │   …                                       │               │
│  │ ▾ 管理  │   …                                       │               │
│  └─────────┴──────────────────────────────────────────┘               │
│                                                                       │
│  底部汇总：已授予 24 / 共 38 个权限点 · 5 个域                          │
└───────────────────────────────────────────────────────────────────────┘
```

**关键决策与依据：**

1. **轴方向：角色为列、权限点为行**（研究共识）。理由：角色只有 3 个（列少），权限点有几十个（行多）。角色作列 → 横向滚动最小化，纵向滚动更自然（ux.stackexchange 建议切换轴）。
2. **域分组 + 可折叠**（订货/库存/品项/报表/管理）。理由：研究指出纯扁平矩阵随模块增加会膨胀到横向滚动灾难；分域折叠 = 渐进披露，把 40 行拆成 5 组 ≤10 行。
3. **三态单元格**（授予/继承/未授予）+ **锁定态**。理由：见 §3.2 token 注释。本期三态中「继承」在本项目当前模型下可能不出现（3 角色非严格继承），但**token 与视觉规范先行定义**，为 Phase 2 自定义角色继承预留，避免届时改版。
4. **冻结左列**（权限点名），用 `position:sticky; left:0` 而非 absolute。理由：研究明确指出矩阵横向滚动时角色列错位的经典坑，sticky 是正解。
5. **本期交互：只读**。内置角色包复选框为 `disabled`（研究共识：系统内置角色锁定，checkbox 禁用 + tooltip「内置角色包，权限由系统定义」）。
6. **底部 "已授予 N / 共 M" 实时计数**（研究共识：live granted/total counter）。
7. **图例常驻**：解释三态与命名格式，降低首次认知负荷。

## 5. 图标方案确认（P0-1 合规）

**结论：复用项目既有内联 SVG 描边图标方案，锁定为全项目唯一图标来源，禁止 emoji。**

| 项 | 规范 |
|----|------|
| 图标库 | **内联 SVG（Lucide 几何风格，stroke-based）**——即 `users.html:31-34,69-71,154-156` 既有做法 |
| 引入方式 | 模板内直接 `<svg>`，**不引入图标字体、不引入 CDN、不新增依赖**（零依赖铁律） |
| 尺寸 | 16px（行内/文字按钮内）/ 20px（工具栏与抽屉按钮内）/ 24px（导航/独立） |
| 线宽 | `stroke-width="2"`，`stroke="currentColor"`，`fill="none"`，`aria-hidden="true"` |
| 新建图标 | 本功能需要：`search`(既有)、`chevron-right`(折叠态，既有多处用 `▸/▾` 字符 → 统一替换为 SVG)、`shield`(权限域"管理")、`box`(订货)、`layers`(库存)、`tag`(品项)、`bar-chart`(报表)、`lock`(锁定态)、`download`(导出)、`x`(关闭，既有)、`eye`(查看权限) |

**emoji 检测**：交付物须通过正则 `[\x{1F300}-\x{1F9FF}\x{2600}-\x{26FF}\x{2700}-\x{27BF}]` 零命中扫描。

**注意**：既有代码用 `▸`/`▾` 字符作折叠标记（`users-admin.css:314,321`）。这两个是**几何符号非 emoji**，但视觉一致性上建议本次统一为 SVG `chevron`（同 stroke 风格）。

### 5.4 权限点命名的 UI 可读化策略（研究重点）

权限点数据库里是 `order.approve` 这种 dot-notation，直接展示对管理员不友好。策略（研究共识）：

| 层 | 展示 | 样式 |
|----|------|------|
| 主展示 | **中文可读名** | 「审批订货」正文 14px |
| 副展示 | dot-notation 代码 | `order.approve` 等宽 12px，`--muted` 色 |
| 悬浮 | tooltip 补全说明 | 「允许审批门店提交的订货单（限当前仓库，DC manager 以上）」 |
| 徽章化（紧凑场景） | 资源段灰 + 动作段粗 | `order` ● **approve**（`.tag` 现有样式基础上分段着色） |

域分组标签用**中性 chip**（不彩虹），域图标（shield/box/layers/tag/bar-chart）承担区分度。

## 6. 组件状态矩阵（核心组件）

| 组件 | Loading | Empty | Error | Populated | Edge |
|------|---------|-------|-------|-----------|------|
| 权限矩阵 | 骨架屏（域分组占位框） | 「暂无权限点定义」+ 说明（本期数据来自常量，理论不空） | 「加载失败」+ 重试 | 域分组 + 三态格 | 权限点 >60 → 强制折叠默认全闭；域 >8 → 纵向滚动 |
| 角色权限抽屉 | 骨架行 | 该角色无权限（禁用角色） | 加载失败 + 重试 | 域分组权限清单 | 权限点清单超长 → 抽屉内独立滚动 |
| 绑定行「查看权限」按钮 | — | — | 浮层失败提示 | 悬浮打开浮层 | 长仓库名截断 ellipsis + title |
| 新建角色按钮 | — | — | — | 禁用 + tooltip「二期」 | — |

**矩阵单元格键盘可达**：单元格用 `<button>` 或 `<input type=checkbox>`（真实元素，非 styled div），带 `aria-pressed`/`checked`；锁定态用 `disabled` 属性（研究共识：让屏幕阅读器报"不可用"而非"看起来不可用"）。本期只读，全部 `disabled` + `aria-label`。

## 7. 响应式策略

| 断点 | 矩阵行为 |
|------|----------|
| ≥1024px | 完整矩阵：冻结列 + 角色列 + 域折叠，单元格 28px，行高 36px |
| 768-1024px | 压缩：单元格 24px，域默认全闭 |
| <768px | **矩阵退化为逐角色手风琴**（每角色一卡，卡内按域列出「权限名 [已授予]」清单），**不做横向滚动**（触摸横滚是灾难） |

触摸目标：移动端手风琴行 ≥44px 高（WCAG 2.5.5）；桌面矩阵单元格 28px 属**鼠标优化**，可接受（键盘可达已保障）。

导航：<768px 用既有 `mobile-nav`（`base.html:114`），权限管理入口暂并入「账号」组，不新增第 N 个底部 Tab（底部导航 ≤5 铁律）。

## 8. 无障碍要点（设计期仅埋点，审计期专项检查）

> 遵循 a11y 审计分离原则：设计期不做过度保守，此处仅记录**必须预留的接口**，具体对比度矩阵在 Phase 2 `audit` 执行。

- 焦点可见：所有可交互元素 `:focus-visible` 用 `outline:2px solid var(--brand); outline-offset:1px`（对齐既有 `users-admin.css:36-40`）。
- 三态单元格**不仅靠颜色**：授予=实心+勾、继承=虚线边框、未授予=空描边、锁定=灰底+锁图标 → 色盲可辨。
- 键盘流：Tab 进出矩阵，方向键在单元格间移动（roving tabindex）。
- `prefers-reduced-motion`：抽屉过渡与 checkout 切换动画降级为无过渡。
- 对比度：`--muted #6b7280` on `--panel #fff` ≈ 4.8:1 达标；矩阵文字承 4.5:1 底线。
